  Hướng 1: Nâng cấp DSA lên 2048/256 (ít thay đổi code nhất)

  Thay p, q hardcode bằng bộ tham số từ FIPS 186-4 Appendix A.1:

  // 2048-bit p, 256-bit q — NIST FIPS 186-4 approved
  const p = new BN('...2048-bit prime...', 16);
  const q = new BN('...256-bit prime...', 16);
  // g tính tương tự: h^((p-1)/q) mod p

  Đạt ~112-bit security. Nhưng đây vẫn là finite-field, chậm và key to.

  ---
  Hướng 2: Chuyển sang Elliptic Curve (khuyến nghị)

  Schnorr threshold blind signature được thiết kế tự nhiên cho ECC. Nhóm (Z_p*, 
  ×) trong code hiện tại tương đương với nhóm điểm EC (E(F_p), +) — chỉ thay
  phép nhân modular bằng phép cộng điểm EC.

  Hiện tại (finite field):    Production (ECC):
  ─────────────────────────   ───────────────────────────────
  g^x mod p              →    x·G  (scalar multiplication)
  a · b mod p            →    A + B (point addition)
  g^a · g^b mod p        →    (a+b)·G
  q (subgroup order)     →    n (curve order)
  p (modulus)            →    loại bỏ, dùng curve arithmetic

  Curve nên dùng:

  Curve: secp256k1
  Dùng khi: blockchain, Bitcoin-compatible
  Security: 128-bit
  Thư viện JS: @noble/curves
  ────────────────────────────────────────
  Curve: P-256 (secp256r1)
  Dùng khi: enterprise, TLS, FIDO2
  Security: 128-bit
  Thư viện JS: @noble/curves
  ────────────────────────────────────────
  Curve: Ed25519
  Dùng khi: performance tối đa, SSH, Signal
  Security: 128-bit
  Thư viện JS: @noble/curves

  Với Schnorr threshold blind, secp256k1 là lựa chọn phổ biến nhất (dùng trong
  FROST, MuSig2, Lightning).

  Cấu trúc thay thế params.js:

  // production-params.js
  const { secp256k1 } = require('@noble/curves/secp256k1');

  function getProductionParams() {
    return {
      // Thay (p, q, g) bằng (curve, n, G)
      curve: secp256k1,
      n: secp256k1.CURVE.n,    // order của nhóm (≈ 256-bit)
      G: secp256k1.ProjectivePoint.BASE,  // generator point
      // scalar mod n thay cho x mod q
      // point·scalar thay cho g^x mod p
    };
  }

  3. utils.js — viết lại

  'use strict';
  const { sha256 } = require('@noble/hashes/sha256');
  const crypto = require('crypto');

  // scalar arithmetic dùng BigInt thay vì BN (noble/curves convention)
  function modN(a, n) {
    const r = a % n;
    return r < 0n ? r + n : r;
  }

  // thay modPow(g, x, p):
  function scalarMultBase(scalar, params) {
    return params.G.multiply(scalar);
  }

  // thay modPow(P, x, p) khi P không phải G:
  function scalarMult(point, scalar) {
    return point.multiply(scalar);
  }

  // thay A.mul(B).umod(p):
  function pointAdd(P, Q) {
    return P.add(Q);
  }

  // thay randomInZqStar(q):
  function randomScalar(n) {
    while (true) {
      const buf = crypto.randomBytes(32);
      const candidate = modN(BigInt('0x' + buf.toString('hex')), n);
      if (candidate !== 0n) return candidate;
    }
  }

  // thay bnToBuffer khi hash điểm — dùng compressed encoding (33 bytes):
  function pointToBuffer(point) {
    return Buffer.from(point.toRawBytes(true)); // true = compressed
  }

  // hash → scalar mod n (thay hashToBN):
  function hashToScalar(buffers, n) {
    const h = sha256.create();
    for (const buf of buffers) h.update(buf);
    return modN(BigInt('0x' + Buffer.from(h.digest()).toString('hex')), n);
  }

  module.exports = {
    modN, scalarMultBase, scalarMult, pointAdd,
    randomScalar, pointToBuffer, hashToScalar,
  };

  Lưu ý: @noble/curves dùng bigint (native) thay vì BN. Nếu muốn ít refactor,
  giữ BN và convert: BigInt(bn.toString()) ↔ new BN(bigint.toString()). Nhưng
  dài hạn nên chuyển hẳn sang bigint.

  4. keygen.js — đổi 2 dòng

  const { scalarMultBase, randomScalar, pointAdd } = require('./utils');

  function generateKeyPair(params) {
    const privateKey = randomScalar(params.n);
    const publicKey = scalarMultBase(privateKey, params);  // d_i · G
    return { privateKey, publicKey };
  }

  function computeCollectivePublicKey(publicKeys, params) {
    // ρ = ∏ ρ_i  →  P_agg = Σ P_i
    return publicKeys.reduce((acc, pk) => pointAdd(acc, pk),
                            params.Point.ZERO);  // identity element
  }

  5. commitment.js — đổi 2 dòng

  function generateCommitment(params) {
    const nonce = randomScalar(params.n);
    const commitment = scalarMultBase(nonce, params);  // k_i · G
    return { nonce, commitment };
  }

  function computeCollectiveCommitment(commitments, params) {
    return commitments.reduce((acc, c) => pointAdd(acc, c),
                              params.Point.ZERO);
  }

  6. blind.js — đổi cách kết hợp (mul → add)

  function blind(message, C, params, P_agg) {
    const { n } = params;
    const alpha = randomScalar(n);
    const beta = randomScalar(n);

    // C' = C + α·G + β·P_agg   (thay vì c · g^α · ρ^β)
    const aG = scalarMultBase(alpha, params);
    const bP = scalarMult(P_agg, beta);
    const Cprime = pointAdd(pointAdd(C, aG), bP);

    // h = Hash(M ‖ C') mod n
    const h = hashToScalar([message, pointToBuffer(Cprime)], n);

    // r = (h - β) mod n
    const r = modN(h - beta, n);

    return { r, alpha, beta, h, Cprime };
  }

  Tối ưu: α·G + β·P_agg có thể tính bằng một call
  Point.multiplyAndAddUnsafe(P_agg, alpha, beta) (nếu thư viện hỗ trợ) — nhanh
  ~30% nhờ Strauss-Shamir.

  7. sign.js — chỉ rename q → n

  function signPartial(ki, di, r, n) {
    // s_i = (k_i - d_i · r) mod n     ← logic giữ nguyên 100%
    return modN(ki - (di * r), n);
  }

  function aggregateSignatures(partialSigs, n) {
    return partialSigs.reduce((s, si) => modN(s + si, n), 0n);
  }

  Đây là phần "đẹp": scalar arithmetic không quan tâm là finite field hay EC.

  9. verify.js — đổi cách kiểm

  function verify(message, h, sPrime, params, P_agg) {
    const { n } = params;

    // C_check = s'·G + h·P_agg     (thay g^s' · ρ^h)
    const sG = scalarMultBase(sPrime, params);
    const hP = scalarMult(P_agg, h);
    const Ccheck = pointAdd(sG, hP);

    const hCheck = hashToScalar([message, pointToBuffer(Ccheck)], n);
    return h === hCheck;
  }

  10. validation.js — thêm validator điểm

  function isValidPointHex(hex, Point) {
    try {
      const p = Point.fromHex(hex);
      p.assertValidity();      // kiểm trên curve, không phải identity
      return !p.equals(Point.ZERO);
    } catch { return false; }
  }

  function isValidScalarHex(hex, n) {
    if (!isValidHex(hex)) return false;
    try {
      const v = BigInt('0x' + hex);
      return v > 0n && v < n;
    } catch { return false; }
  }

  Cực kỳ quan trọng: mọi điểm nhận từ network phải gọi assertValidity. Nếu
  không, kẻ tấn công có thể gửi điểm "giả" (không thuộc curve) → leak khóa qua
  invalid-curve attack. Đây là pitfall số 1 khi tự implement EC.

  Độ phức tạp tiệm cận

  Cùng là O(log n) cho 1 scalar mult, nhưng hằng số nhỏ hơn rất nhiều vì:
  - bn.js thực hiện modular reduction trên số 1024-bit (Montgomery)
  - @noble/curves thực hiện trên field 256-bit + dùng pre-computed tables cho G

  addition

  ---
  Cảnh báo bảo mật (không liên quan group nhưng phải nói)

  Lược đồ Schnorr Blind hiện tại (Stadler-Camenisch-style) dễ bị ROS attack khi
  attacker mở đồng thời nhiều phiên ký (parallel blind signing) — Wagner 2002,
  Benhamouda et al. 2021. Áp dụng cho cả finite-field lẫn EC version.

  Nếu mỗi user chỉ được ký 1 lần (như trong voting với enforcement ở chaincode)
  thì OK. Nếu signing service mở concurrent sessions với cùng 1 user, cần:
  - MuSig2 (BIP 327) cho threshold
  - FROST (RFC 9591) cho threshold + blind variants
  - Hoặc rate-limit nghiêm ngặt: max_concurrent_sessions_per_user = 1

  Đây là vấn đề giao thức, không phải nhóm — đổi sang EC không tự sửa được.

     EC-Schnorr Migration: secp256k1 + @noble/curves

     Context

     Hệ thống hiện đang dùng DSA 1024/160 (finite field) cho lược đồ Schnorr
     Blind Multisignature — chỉ ~80-bit security, đã bị NIST deprecated từ 2013.
      Toàn bộ crypto được build trên bn.js. Migration sang secp256k1 mang lại:

     - 128-bit security (so với 80-bit hiện tại)
     - ~5–25× nhanh hơn ở mỗi phép scalar mult
     - ~4× payload nhỏ hơn trên wire và DB (33-byte points thay 128-byte
     modulus)
     - Loại bỏ hoàn toàn bn.js — dùng native bigint qua @noble/curves
     (isomorphic Node + browser)
     - Bỏ duplicate code giữa crypto-core (Node) và client-web/src/lib/crypto.js
      (browser) — @noble/* chạy trên cả hai môi trường

     Toán học gốc của lược đồ Stadler-style blind Schnorr không đổi — chỉ thay
     nhóm (Z_p*, ×) bằng nhóm điểm secp256k1 (E(F_p), +). Toàn bộ flow API và
     field name trên wire giữ nguyên; chỉ kích thước hex thay đổi.

     ▎ Lưu ý ROS attack: scheme Stadler blind Schnorr (cả finite-field lẫn EC) 
     ▎ dễ bị ROS attack khi mở concurrent sessions — đây là vấn đề protocol, 
     ▎ không phải nhóm. Hệ thống hiện đang enforce 1-vote-per-voter ở chaincode 
     ▎ + DB, nên rủi ro thấp; ngoài scope migration này.
